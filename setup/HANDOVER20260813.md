## 5. The two real deployment problems, and they share one fix

Both are in the **view definitions**, and both are invisible until something reads a view.

**No `SUPER` grant.** `mysqldump` writes every view with `DEFINER=\`user\`@\`host\``; restoring a
view whose definer you cannot become fails outright. At least nine views are affected.

**Views carry the source schema name.** MySQL normalises view definitions and qualifies table
references, so `SELECT … FROM plays` dumps as ``SELECT … FROM `gplan_pbm`.`plays` `` and points
at a database that does not exist on the host.

```bash
# No --databases -- keeps CREATE DATABASE / USE out, so the dump is schema-agnostic
mysqldump --single-transaction --routines --triggers=FALSE gplan_pbm \
  | sed -E 's/DEFINER=`[^`]*`@`[^`]*` ?//g;
            s/SQL SECURITY DEFINER/SQL SECURITY INVOKER/g;
            s/`gplan_pbm`\.//g' \
  > gplan_pbm_portable.sql

grep -cE 'DEFINER|gplan_pbm' gplan_pbm_portable.sql   # must be 0
```

## 7. Working practices adopted this session

- **Diagnostic output must name its own source.** Anything that will be pasted into a chat, doc
  or ticket should print its own host, database and version — by the time it is read, the URL bar
  is gone. `whoami.php` is the standing implementation. This one is Alan's, and it came from a
  stale clipboard paste costing an hour of misdiagnosis.
- **Don't fingerprint a server with default values.** PHP's stock `php.ini` (2M / 8M / 30s /
  128M) matches on any un-customised box. *Matching* defaults prove nothing; *differing* values
  do prove different machines.
- **When evidence contradicts a conclusion, first ask whether the two observations reached the
  same place** — before inventing a mechanism that reconciles them. A plausible mechanism will
  pass its own simulation. This is `lessons.md` §25 (the game 9621 near-miss) in a new costume.
- **State environment findings as actions, not observations.** An EOL PHP finding was recorded
  and then softened to "not a blocker if it can't be changed", which turned an action into a
  remark. `lessons.md` §21 applies to environment findings as much as to bugs.
- **A deploy manifest beats an rsync.** Three artefacts turned up this session that existed on
  disk while appearing in no list: `example.php`, `team_diag.php`, `probe/`.

## 8. The pattern worth carrying forward

Documents drifted from the code in **three different directions** this session, and each cost
real time:

| Doc | Said | Reality |
|---|---|---|
| `security.md` §4 | access gates untested | tested and working for months |
| `schema.md` §13 | `games.label` affects three pages | never audited |
| `findings-gpbm_uk…` | probe folder deleted | nobody had checked (it was, by luck) |

Same failure, opposite directions: a done thing recorded as pending, a to-check recorded as
settled, and an unverified thing recorded as done. `lessons.md` §21 already says a document is
not evidence that something was fixed — it is equally not evidence that something is broken.

**Practical consequence for these documents.** Most of what the three new findings docs contain
is measured — probe results, grants, format survey, environment matrix. Some is inference in the
same voice. Treat anything without a stated observation behind it as a claim to check.
